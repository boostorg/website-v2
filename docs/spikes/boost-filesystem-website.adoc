[#about]
== About

Boost.Filesystem provides portable facilities to query and manipulate paths, files,
and directories — the library that C++17's std::filesystem was modeled on.

[source,cpp]
----
#include <boost/filesystem.hpp>
#include <iostream>

namespace fs = boost::filesystem;

int main() {
    fs::path p{"/usr/include"};
    if (fs::exists(p) && fs::is_directory(p))
        std::cout << p << " — "
                  << std::distance(fs::directory_iterator(p),
                                   fs::directory_iterator())
                  << " entries\n";
}
----


[#playground]
== Playground

// Self-contained so it runs on godbolt: lists the current directory.

[source,cpp]
----
#include <boost/filesystem.hpp>
#include <iostream>

namespace fs = boost::filesystem;

int main() {
    for (const auto& entry : fs::directory_iterator("."))
        std::cout << entry.path().filename().string() << '\n';
}
----


[#designed-for]
== Designed for

=== Portable paths
Manipulate paths, filenames, and extensions the same way across Windows, macOS,
and Linux.

=== Filesystem operations
Query, create, copy, and remove files and directories through a single portable API.

=== Directory iteration
Walk directory trees with directory_iterator and recursive_directory_iterator.

=== Basis for std::filesystem
The reference implementation that the C++17 std::filesystem library was based on.

[#freeform]
== Boost.Filesystem vs. std::filesystem

// A free-form card: your own heading + any content (paragraphs, lists,
// links, code). Rendered as-is into a single card on the page.

C++17 adopted `std::filesystem`, modeled on this library. Prefer Boost.Filesystem when:

* You target a compiler whose `std::filesystem` is incomplete or unshipped.
* You need features that never made it into the standard, such as
  `unique_path` or the wider set of portable error-handling overloads.
* You want a single API that behaves identically across toolchains and Boost releases.

For new code on a modern toolchain with no such constraints, `std::filesystem`
is the lighter-weight default.
