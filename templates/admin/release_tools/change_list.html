Synchronize release library data

Repairs a release whose libraries show Unknown where an author should be. Press Synchronize on the release you want to repair; each row has its own button.

Authors are not stored on the library. They are stored per release, and they come from the meta/libraries.json that each library ships in the release's own Git tag. So the job does two things, in this order:

  1. re-reads that release's libraries from GitHub into the database, and
  2. binds the authors named in what it just read.

The order matters: the second step can only bind what the first step wrote. A release left with the first step done and not the second is exactly how one ends up rendering Unknown.

It only touches the release you press. No author is removed, and no author is copied from one release to another. It is safe to run twice.

Reading the columns

  • Needs synchronizing is libraries with no author that this job is worth running for: either their authors are named upstream but not stored here yet, or their metadata was never read at all. On old releases a residue can remain after a successful run, because some libraries shipped no meta/libraries.json at that tag for anything to be read from. Whatever is left after one run will not clear on a second.
  • No author upstream is a handful of libraries whose own meta/libraries.json names no author at all. They show Unknown on the site and always will. Synchronizing cannot change them, so they are counted here and not in the column beside it. A small number in this column is normal and is not a fault.

Point releases such as 1.91.0-1 are read from their base release, because their libraries are not tagged separately and they ship no documentation of their own.

Not to be confused with Update Authors & Maintainers on the Library page, which rebuilds every release from scratch and can overwrite the authors of older releases that are already correct.
